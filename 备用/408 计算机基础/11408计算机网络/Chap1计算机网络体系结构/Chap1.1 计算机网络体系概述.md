# Chap1.1 计算机网络体系概述

## 1.计算机网络的定义

(注:计算机网络的定义没有统一的定义)

定义:通过**通信链路**和**网络设备**,将分散在不同地理位置的计算机串联起来,遵循统一的**通信协议**,实现**数据交换**,**资源共享**,**协同工作**



## 2.计算机网络的组成

计算机组成的三部分:\[硬件]\[软件]\[协议]

>硬件:\[主机:电脑设备/移动设备]\[网络设备:交换机路由器]\[链路:有线无线链路]
>
>>   其中主机和网络设备统称为节点
>
>软件:\[网络操作系统:Windows/Linux]\[应用软件:浏览器/客户端]
>
>协议:**控制网络通信的规则**的集合\[规定了网络传输数据时遵循的规范]
>
>>   Eg;InterNet因特网是最大的应用最广泛的互联网,采用\[TCP/IP模型+大量协议]
>>
>>   $\to$TCP/IP协议族
>>
>>   Internet的结构\[工作方式上看]:边缘部分:连接在因特网上的设备(主机)
>>
>>   Internet的结构\[工作方式上看]:核心部分:**大量异构型网络**和**连接这些网络的路由器**

## 3.计算机网络的功能

计算机网络的功能\[1]:(主要)数据通信:是计算机网络的**基础功能**,实现设备之间高效可靠的信息传输

计算机网络的功能\[2]:(主要)资源共享:**基于数据传输**$\to$集中化/分布式架构$\to$共享硬件软件数据,降本增效

计算机网络的功能\[3]:(主要)分布式处理:基于**数据传输**和**资源共享**$\to$网络中多个计算机系统的协同工作

计算机网络的功能\[4]:可靠性保障:**基于冗余设计/错误检测/恢复机制**$\to$确保服务连续性

计算机网络的功能\[5]:负载均衡与流量优化:动态分配资源以避免拥塞,提高响应速度

计算机网络的功能\[6]:安全防护:利用加密技术/防火墙/访问控制,抵御攻击

计算机网络的功能\[7]:远程管理与监控:实施诊断故障,并且调整网络策略

计算机网络的功能\[8]:标准化互操作性:统一协议实现异构设备无缝协作

## 4.计算机网络的分类

###### 1. 按分布范围分类(物理覆盖决定网络技术)

\[广域网 WAN]:覆盖几十到几千千米\(互联网核心),跨越长距离,连接节点的链路大多是高速链路,核心技术是交换技术

\[城域网 MAN]:覆盖\[5~50km]\(城市/街区级),大多直接采用\[以太网技术]

\[局域网 LAN]:覆盖\[几十到几千米],使用主机通过高速线路相连,传统核心技术是\[广播技术]

\[个人区域网 PAN]:覆盖个人工作区,使用\[无线技术]连接消费电子设备

###### 2. 按传输技术分类(底层通信机制)

\[广播式网络]:所有计算机\[共享公共通信信道],发送的分组会被所有机器收听,通过检查\[目的地址]决定是否接收；\[局域网]基本采用此技术

\[点对点网络]:物理线路连接一对计算机,非直连主机必须通过中间节点进行存储和转发

###### 3. 按拓扑结构分类(逻辑结构设计)

\[总线形]:\[单根传输线]优点:建网容易省线路；缺点:重载时通信效率低,\[对单点故障敏感]

\[星型]:终端全部连接中央设备\(交换机/路由器)优点:集中控制管理；缺点:成本高,对中央设备故障极度敏感

\[环形]:首尾相连成环,信号\[单向传输]\(如令牌环网)

\[网状]:节点拥有\[至少两条路径],主要用于\[广域网]优点:\[可靠性极高]；缺点:路由控制复杂,线路成本高

###### 4. 按使用者与传输介质分类

使用者:\[公用网]\(电信公司建造,付费使用)

​      \[专用网]\(铁路/军队等特定部门内部使用,不对外开放)

传输介质:\[有线]\(双绞线、同轴电缆)

​        \[无线]\(蓝牙、微波、无线电)

###### 5. 数据交换方式核心脉络

\[电路交换]:通信前需建立连接,通信期间\[独占物理信道],实时性强但线路利用率低

\[报文交换]:采用\[存储转发]机制,以完整报文为单位传输,延迟大,需节点有大容量缓存

\[分组交换]:采用\[存储转发]机制,将数据切割为\[固定大小的分组],缓冲区易于管理,线路利用率高,是\[当前计算机网络的主流技术]

## 5. 电路交换 / 报文交换 / 分组交换

###### 1. 三大数据交换方式核心机制

[电路交换 Circuit Switching]:
>概念本质: 通信前需在发送端与接收端之间建立一条**专用的物理通路**。
>
>通信三阶段: 建立连接(呼叫/建立物理信道) $\to$ 通话(全程独占物理通路) $\to$ 释放连接(拆除物理信道)。
>
>核心特征: ==独占物理带宽==。即使双方在通话期间没有任何数据传输(静默期)，信道资源也无法被其他用户使用。
>
>优缺点剖析:
>>优点:
>>
>>(1) 传输时延极小: 物理通路直通，无中间节点存储转发延迟。
>>
>>(2) 严格按序到达: 沿固定物理链路传输，不存在数据报失序问题。
>>
>>(3) 实时性极高: 独占信道，通信双方宛如直连，适合传统语音电话。
>>
>>缺点:
>>
>>(1) 建立连接耗时长: 呼叫握手需耗费端到端传播时延。
>>
>>(2) 线路利用率极低: 计算机通信具有突发性，独占信道导致大部分时间信道空闲浪费。
>>
>>(3) 缺乏差错控制与灵活性: 中间交换设备仅作信号透传，不作差错校验与数据缓存；任何节点损坏将导致物理链路中断。

[报文交换 Message Switching]:
>概念本质: 以完整的**用户报文(Message)**为单位进行传输，无需提前建立连接。
>
>核心机制: ==存储转发(Store and Forward)==。报文携带目标地址，中间节点(交换机)接收完整报文、暂存并检验无误后，寻找路由转发表转发给下一节点。
>
>优缺点剖析:
>>优点:
>>
>>(1) 无需建立连接: 随时发送，动态分配信道。
>>
>>(2) 线路利用率高: 多个通信共享物理信道，按需占用。
>>
>>缺点:
>>
>>(1) 传输时延大且抖动剧烈: 每个中间节点必须**完整收齐全报文**并校验完毕后才开始向下一跳转发。
>>
>>(2) 节点存储开销极大: 报文长度无上限限制，交换设备需要配备海量磁盘或大内存以防溢出。
>>
>>(3) 差错重传开销惨重: 报文中哪怕只有 1 个比特出错，整个长报文必须全盘重传。
>>
>><font color=deeppink>【历史结论】: 报文交换是存储转发思想的早期雏形，现已被计算机互联网全盘淘汰。</font>

[分组交换 Packet Switching]:
>概念本质: 采用存储转发机制，但在源主机端将长报文**严格切割为带长度上限的短数据块——分组(Packet / 数据包)**，每个分组附加首部(Header)后独立转发。
>
>两大传输模式:
>>[模式1: 数据报方式 (Datagram)]
>>
>>$\to$ 无连接服务(互联网核心机制，如IP层)。
>>
>>$\to$ 每个分组独立寻路，中间路由根据转发表单独决定下一跳。
>>
>>$\to$ 分组到达目的端可能**失序、重复或丢失**，由接收端或上层协议负责重新排序组装。
>>
>>[模式2: 虚电路方式 (Virtual Circuit)]
>>
>>$\to$ 面向连接服务(如传统X.25、ATM网络)。
>>
>>$\to$ 数据传输前先建立一条逻辑通路(虚电路VC)，所有分组沿该通路按序流动，通信结束释放虚电路。
>>
>>$\to$ 兼具电路交换的有序性与分组交换的高利用率，但核心路由器需要维护连接状态表。
>
>优缺点剖析:
>>优点:
>>
>>(1) 流水线并行转发(加速传输): 后一个分组由源端推入链路的同时，前一个分组已在下游路由器转发，形成**高度重叠的流水线**。
>>
>>(2) 存储开销小、内存易管理: 分组设定最大长度(如以太网MTU通常1500B)，交换节点只需分配固定大小的高速内存缓冲区，无爆仓风险。
>>
>>(3) 差错重发粒度精细: 某个分组损坏仅需重发该分组，极大降低信道重传开销。
>>
>>(4) 突发流量适应性强: 采用**统计时分复用(Statistical TDM)**，信道带宽动态按需分配。
>>
>>缺点:
>>
>>(1) 协议首部存在开销: 每个分组都携带源/目的地址与控制信息，传输有效载荷比例略有下降。
>>
>>(2) 节点仍有排队时延: 突发流量汇聚时，路由器输入输出队列会出现排队延迟，严重时导致丢包。

###### 2. 三种数据交换方式横向对比矩阵 (408高频考点)

| 比较维度 | 电路交换 (Circuit Switching) | 报文交换 (Message Switching) | 分组交换 (Packet Switching) |
| :--- | :--- | :--- | :--- |
| **物理连接** | 必须预先建立物理专用信道 | 无连接 | 数据报无连接 / 虚电路建立逻辑连接 |
| **传输单位** | 连续比特流 (Bit Stream) | 完整长报文 (不定长) | 分割后的短分组 (定长或设上限) |
| **转发机制** | 物理直通传输 (无存储转发) | 存储转发 (整报文落盘/缓存) | 存储转发 (内存分组队列流水线) |
| **信道分配** | 独占物理带宽 (静态时分/频分) | 动态分配 | 动态统计多路复用 (按需抢占) |
| **传输时延** | 建立连接耗时，通信过程时延极小 | 极大 (大报文逐跳完整接收) | 较小 (流水线重叠转发，延迟极低) |
| **节点缓存** | 无需大缓存 (仅作电/光信号转发) | 需海量缓存/大容量磁盘 | 仅需极小高速内存缓冲区 |
| **差错重传** | 端系统负责，无节点检错机制 | 整份长报文全量重发 | 仅重发损坏的个别分组 |
| **适用场景** | 连续大批量数据传输、实时语音/视频 | 历史早期低速电报系统 | 突发性计算机网络通信 (因特网基石) |

###### 3. 交换方式的核心选型原则

>传送海量连续数据且要求高实时性(如电话骨干网) $\to$ ==优先选用电路交换==。
>
>传输突发性强、间歇性计算机数据(如Web访问、文件下载) $\to$ ==优先选用分组交换==。
>
>长报文若直接存储转发会导致中间节点严重阻塞，故计算机网络严禁直接采用报文交换。

## 6. 计算机网络的性能指标

###### 1. 速率 (Rate / Data Rate)

>定义: 计算机网络中主机在数字信道上传送数据的速度，又称**数据率**或**比特率**。
>
>基本单位: $\text{b/s}$ (即 $\text{bit/s}$ 或 $\text{bps}$)。
>
>常用衍生单位: $\text{kb/s} \to \text{Mb/s} \to \text{Gb/s} \to \text{Tb/s} \to \text{Pb/s}$。
>
><font color=red>【408绝对避坑红线: 通信领域与存储领域的进位法则】</font>
>
>>通信领域(速率/带宽): 按十进制 **$10^3$** 进位！
>>
>>$1\text{ kb/s} = 10^3\text{ b/s} = 1000\text{ b/s}$
>>
>>$1\text{ Mb/s} = 10^6\text{ b/s} = 10^3\text{ kb/s}$
>>
>>$1\text{ Gb/s} = 10^9\text{ b/s} = 10^3\text{ Mb/s}$
>>
>>存储领域(文件大小/内存容量): 按二进制 **$2^{10}$** 进位！
>>
>>$1\text{ Byte} = 8\text{ bit}$
>>
>>$1\text{ KB} = 2^{10}\text{ B} = 1024\text{ B}$
>>
>>$1\text{ MB} = 2^{20}\text{ B} = 1024\text{ KB}$
>>
>>$1\text{ GB} = 2^{30}\text{ B} = 1024\text{ MB}$
>>
>><font color=deeppink>审题秘笈: 计算传输时间时，文件体积先乘 8 换算为 bit 并使用 $2^{10}$ 展开，而信道带宽速率使用 $10^3$ 展开！</font>

###### 2. 带宽 (Bandwidth)

>频域视角(信号处理): 信号所拥有的频带宽度，单位为赫兹($\text{Hz}$、$\text{kHz}$、$\text{MHz}$)。
>
>时域视角(计算机网络/408常考): 网络通信信道传送数据的能力，即**信道上所能达到的最高极限数据率**，单位为 $\text{b/s}$。
>
><font color=red>【本质辨析】: “带宽变宽”并不代表电磁波在信道上的物理传播速度变快！</font>
>
>>电磁波在介质中的物理传播速度由介质本身的物理性质决定(光纤中约 $2.0 \times 10^8\text{ m/s}$)。
>>
>>增大带宽，只是在单位时间内从发送端向线路上**注入了更多密集的比特**，缩短了发送耗时！

###### 3. 吞吐量 (Throughput)

>定义: 单位时间内通过某个网络(或信道、接口)的**实际数据量**，单位常为 $\text{b/s}$。
>
>关系透析: 带宽代表**最大理论传输能力(水管的最大截面积)**；吞吐量代表**网络当前的实际流通速率(水管里实际流过的水量)**。
>
>瓶颈制约: 串联端到端链路中，端到端吞吐量取决于全路径上的最小链路带宽(即**木桶效应 / 瓶颈链路 Bottleneck Link**):
>
>$$\text{端到端吞吐量} \le \min\{R_1, R_2, \dots, R_k\}$$

###### 4. 时延 (Delay / Latency)

>定义: 数据(一个报文或分组)从网络的一端传送到另一端所需要的总时间。
>
>总时延数学模型:
>
>$$总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延$$
>
>[1] 发送时延 (Transmission Delay / 传输时延)
>
>>$$t_{\text{trans}} = \frac{\text{数据帧长度 (bit)}}{\text{发送速率 / 信道带宽 (b/s)}}$$
>>
>>发生位置: **主机或路由器的发送器内部(网卡)**。
>>
>>物理过程: 数据块的第一个比特推上信道开始，到最后一个比特完全推上信道为止所耗费的时间。
>
>[2] 传播时延 (Propagation Delay)
>
>>$$t_{\text{prop}} = \frac{\text{信道物理长度 (m)}}{\text{电磁波在信道中的传播速率 (m/s)}}$$
>>
>>发生位置: **两节点之间的物理传输介质内部(铜线/光纤/无线空间)**。
>>
>>电磁波常用传播速率常数(408计算基础):
>>
>>$\to$ 真空 / 空气中无线电波: 约 $3.0 \times 10^8\text{ m/s} = 300\text{ km/ms}$。
>>
>>$\to$ 铜线(双绞线/同轴电缆): 约 $2.3 \times 10^8\text{ m/s} = 230\text{ km/ms}$。
>>
>>$\to$ 光纤: 约 $2.0 \times 10^8\text{ m/s} = 200\text{ km/ms}$。
>
>[3] 处理时延 (Processing Delay)
>
>>发生位置: **中间节点(路由器/交换机)的主板 CPU / 专用转发表芯片**。
>>
>>物理过程: 节点收到分组后，解析首部、执行差错校验(如CRC)、查找路由表以确定输出接口。
>
>[4] 排队时延 (Queuing Delay)
>
>>发生位置: **路由器的输入队列与输出队列缓冲区**。
>>
>>物理过程: 分组在输入端口排队等待交换结构处理，处理完毕后在输出端口排队等待物理链路空闲发送。
>>
>>动态特性: 排队时延取决于当前网络的拥塞程度；若网络负载过重导致缓存溢出，分组将被直接丢弃(产生丢包)。
>
><font color=deeppink>【形象化模型: 汽车与高速公路收费站】</font>
>
>>发送时延: 车队通过收费站领卡的时间(由收费站窗口办理速率决定)。
>>
>>传播时延: 汽车在高速公路上跑完 100 公里耗费的时间(由公路限速与车速决定)。
>>
>>处理时延: 汽车在中间立交桥查看路标、决定转向耗费的时间。
>>
>>排队时延: 汽车在收费站前大排长龙等待的时间。

###### 5. 分组交换流水线传输时延推导 (408核心高频大题模型)

>场景设定:
>
>>数据总量为 $D$ 比特，划分为 $n$ 个等长分组，每个分组长度为 $L$ 比特(此处暂忽略首部开销，即 $D = n \times L$)。
>>
>>源主机与目的主机之间由 $k-1$ 个路由器相连，共有 $k$ 段物理链路，每段链路带宽均为 $R$，传播时延均为 $\tau$。
>>
>>忽略节点处理时延与排队时延。
>
>流水线时序推导过程:
>
>>第一阶段: 源端连续发送完第 1 个分组耗时 $t_1 = \frac{L}{R}$。
>>
>>第二阶段: 该分组经过 $k$ 段链路的传播耗时 $k \cdot \tau$；在中间 $k-1$ 个路由器分别经历存储转发各耗时 $\frac{L}{R}$，共耗时 $(k-1)\frac{L}{R}$。
>>
>>因此，第 1 个分组完全到达目的端的时间为:
>>
>>$$T_1 = k \cdot \frac{L}{R} + k\tau$$
>>
>>第三阶段: 由于存储转发形成了流水线重叠，在第 1 个分组到达后，后续的每一个分组在流水线满负荷状态下，每隔一个发送时延 $\frac{L}{R}$ 便会紧随其后到达目的端！
>>
>>剩余 $n-1$ 个分组完全接收额外需要耗时: $(n-1)\frac{L}{R}$。
>
>总时延归纳公式:
>
>$$T_{\text{总}} = T_1 + (n-1)\frac{L}{R} = (n + k - 1)\frac{L}{R} + k\tau$$
>
><font color=deeppink>【宏观透视统一口诀】: 总耗时 = 源端连续发送全部 $n$ 个分组的总时间 $n \cdot \frac{L}{R}$ + 最后一个分组在沿途 $k-1$ 个路由器上的存储转发延迟 $(k-1)\frac{L}{R}$ + 沿途 $k$ 段链路的总传播时延 $k\tau$！</font>

###### 6. 时延带宽积 (Bandwidth-Delay Product, BDP)

>数学定义:
>
>$$\text{时延带宽积} = 传播时延 \times 信道带宽 = t_{\text{prop}} \times R$$
>
>单位: $\text{秒} \times \frac{\text{bit}}{\text{秒}} = \text{bit}$。
>
>物理意义(圆柱管道模型):
>
>>将链路想象成一条管道，信道带宽是管道的截面积，传播时延是管道的长度。
>>
>>时延带宽积表示**当发送端持续发送，且发送的第 1 个比特刚好到达接收端的一刹那，整条物理链路管道内所能容纳的最大比特数量**！
>>
>>因此，时延带宽积又被称为==以比特为单位的链路长度==。
>
>工程价值:
>
>>时延带宽积决定了网络通信中为了充分利用链路信道，滑动窗口协议(TCP)所需的最小发送窗口尺寸！

###### 7. 往返时间 (Round-Trip Time, RTT)

>定义: 从发送方发送数据开始，到发送方收到接收方的确认信息(ACK)所经历的总时间。
>
>组成包含:
>
>$$\text{RTT} = 双向传播时延 + 接收端处理确认时延 + 沿途排队时延$$
>
>典型应用与考点:
>
>>卫星地球同步轨道链路: 卫星距地面约 $36000\text{ km}$，单程传播时延即达 $\frac{36000\times 10^3\text{ m}}{3\times 10^8\text{ m/s}} = 120\text{ ms}$，因此地球站到卫星再返回地面的典型 RTT 高达 $240\sim 270\text{ ms}$。

###### 8. 利用率 (Utilization)

>分类:
>
>>(1) 信道利用率: 某信道有百分之几的时间是被数据通过占用的。
>>
>>(2) 网络利用率: 全网所有信道利用率的加权平均值。
>
>利用率与时延的排队论关系模型:
>
>$$D = \frac{D_0}{1 - U}$$
>
>>$D_0$: 网络完全空闲时的传输时延。
>>
>>$D$: 网络当前的实际时延。
>>
>>$U$: 整体网络利用率 ($0 \le U < 1$)。
>
><font color=red>【408致命命题陷阱: 利用率绝非越高越好！】</font>
>
>>当利用率 $U \to 0$ 时: $D \approx D_0$，网络极为通畅但信道资源闲置浪费。
>>
>>当利用率 $U = 50\%$ 时: $D = 2D_0$，网络时延已经翻倍！
>>
>>当利用率 $U \to 100\%$ 时: 分母趋近于 0，时延 $D \to \infty$！网络产生恶性拥塞排队，导致大面积超时丢包。
>>
>>结论: 衡量良好运行的网络，其利用率通常应控制在合理区间(一般不超过 50%)，一旦超过必须规划扩容！

>   ###### **1. [2013 统考真题] 考查分组交换流水线计算**
>
>   主机甲通过 1 个路由器(采用存储转发方式)与主机乙互联，两段链路的数据传输速率均为 $10\text{ Mb/s}$，主机甲向主机乙发送一个大小为 $8\text{ Mbit}$ 的报文。若链路传播时延与路由器处理时延均忽略不计，则下列关于发送方式与总耗时的描述中，正确的是：( )
>
>   | A. 若直接采用报文交换，总耗时为 0.8s | B. 若报文切分为 1000 个等长分组，总耗时约为 0.8008s |
>   | :--- | :--- |
>   | C. 采用分组交换时，切分的分组越多，总时延一定越小 | D. 无论何种交换方式，中间路由器都不需要缓存完整数据 |
>
>   **【解析与陷阱剖析】**：答案为 **B**。
>
>   > A选项错误分析:
>   >
>   > 报文大小为 $8\text{ Mbit}$，单段链路传输时延 $t = \frac{8\text{ Mbit}}{10\text{ Mb/s}} = 0.8\text{ s}$。
>   >
>   > 报文交换下，主机甲向路由器发送需 0.8s；路由器完整接收后，再向主机乙发送需 0.8s。
>   >
>   > 因此报文交换总耗时为 $0.8 + 0.8 = 1.6\text{ s}$。
>   >
>   > B选项正确推导:
>   >
>   > 切分为 1000 个分组，每个分组大小为 $L = \frac{8\text{ Mbit}}{1000} = 8\text{ kbit} = 8000\text{ bit}$。
>   >
>   > 每个分组发送时延 $t = \frac{8000\text{ bit}}{10\times 10^6\text{ b/s}} = 0.8\text{ ms} = 0.0008\text{ s}$。
>   >
>   > 共有 $k=2$ 段链路(经过 1 个路由器)，套用流水线公式:
>   >
>   > $$T_{\text{总}} = (n + k - 1)t = (1000 + 2 - 1) \times 0.0008\text{ s} = 1001 \times 0.0008\text{ s} = 0.8008\text{ s}$$
>   >
>   > C选项陷阱: 分组并非切得越小越好！每个分组均带有固定首部开销，当分组切得过小时，首部开销占比过大，且过多的分组会使路由器的排队与路由处理开销剧增，总时延反而会增大！
>   >
>   > D选项错误: 存储转发机制的核心要求就是必须在中间节点完整接收并缓存分组或报文。
>
>   ***
>
>   ###### **2. [经典选择题] 传输速率与传播速率概念辨析**
>
>   在下列关于“网络提速”的各种论述中，物理概念完全正确的是：( )
>
>   | A. 将家庭宽带由 100 Mbps 升级为 1000 Mbps，光纤中电磁波的传播速度提高了 10 倍 | B. 信号在信道中的传输速率越高，其传播时延越小 |
>   | :--- | :--- |
>   | C. 提高信道带宽能有效减小数据的发送时延 | D. 传播时延是光信号在光纤两端编解码所消耗的时间 |
>
>   **【解析与陷阱剖析】**：答案为 **C**。
>
>   > <font color=red>致命辨析: 传输速率(发送速率) vs 传播速率！</font>
>   >
>   > A/B选项错误:
>   >
>   > 宽带从 100M 升到 1000M，提升的是网卡发送适配器向线路上注入比特的**发送速率**(由接口时钟频率与信道带宽决定)。
>   >
>   > 光纤中电磁波的**传播速率**永远由物理介质折射率决定(光速除以折射率，约 $2.0\times 10^8\text{ m/s}$)，绝不随带宽变化！
>   >
>   > C选项正确: 发送时延 $t = \frac{\text{数据量}}{\text{带宽}}$，带宽增加，发送时延成反比减小。
>   >
>   > D选项错误: 光信号在线路两端编解码的时间属于处理时延或发送时延；传播时延是电磁波在光纤内部传播物理距离耗费的时间。
>

>
>   ###### **3. [高频考点] 电路交换与分组交换的本质辨析**
>
>   下列关于数据交换方式的叙述中，错误的是：( )
>
>   | A. 电路交换适用于传输实时性强、突发性小的数据 | B. 分组交换中，数据报方式无法保证分组按序到达目的端 |
>   | :--- | :--- |
>   | C. 虚电路方式在建立连接后，通信节点间独占物理链路 | D. 报文交换与分组交换均不需要预先建立端到端的物理连接 |
>
>   **【解析与陷阱剖析】**：答案为 **C**。
>
>   > C选项是经典偷换概念陷阱:
>   >
>   > 虚电路(Virtual Circuit)建立的是**逻辑连接**，并非物理连接！
>   >
>   > 在虚电路通信中，多个逻辑虚电路依然可以**统计时分复用**共享同一条物理链路，中间链路并没有被某条虚电路单独物理独占。
>   >
>   > 只有电路交换才真正“独占物理信道”。因此 C 叙述错误，选 C。
>

>   ###### **4. [单位换算陷阱大题精析]**
>
>   在带宽为 $1\text{ Gb/s}$ 的全双工对称信道上，通过单段长度为 $1000\text{ km}$ 的光纤传输一个大小为 $125\text{ MB}$ 的数据文件(光纤信号传播速度为 $2.0 \times 10^8\text{ m/s}$，忽略处理与排队时延)。求该文件的发送时延、传播时延与链路时延带宽积。
>
>   **【规范计算推导】**：
>
>   > 第一步: 单位精确换算
>   >
>   > 文件体积(二进制):
>   >
>   > $$125\text{ MB} = 125 \times 2^{20}\text{ B} = 125 \times 1048576 \times 8\text{ bit} = 1048576000\text{ bit} \approx 1.048576 \times 10^9\text{ bit}$$
>   >
>   > 信道带宽(十进制):
>   >
>   > $$1\text{ Gb/s} = 10^9\text{ b/s}$$
>   >
>   > 第二步: 计算发送时延
>   >
>   > $$t_{\text{trans}} = \frac{125 \times 2^{20} \times 8\text{ bit}}{10^9\text{ b/s}} = \frac{1048576000}{10^9} \approx 1.0486\text{ s}$$
>   >
>   > 第三步: 计算传播时延
>   >
>   > $$t_{\text{prop}} = \frac{1000\text{ km}}{2.0 \times 10^8\text{ m/s}} = \frac{10^6\text{ m}}{2.0 \times 10^8\text{ m/s}} = 0.005\text{ s} = 5\text{ ms}$$
>   >
>   > 第四步: 计算时延带宽积
>   >
>   > $$\text{BDP} = t_{\text{prop}} \times R = 0.005\text{ s} \times 10^9\text{ b/s} = 5 \times 10^6\text{ bit} = 5\text{ Mbit}$$
>   >
>   > <font color=red>【警示总结】: 若错误地将 125MB 当作 $125 \times 10^6 \times 8 = 10^9\text{ bit}$ 计算，发送时延就会算出错误的 1.0s！在 408 评分细则中，单位进位混淆将直接失分！</font>
