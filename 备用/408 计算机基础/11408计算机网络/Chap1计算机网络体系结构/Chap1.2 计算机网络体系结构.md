# Chap1.2 计算机网络体系结构

## 1. 计算机网络体系结构概述

###### 1. 体系结构的本质与分层设计哲学

[体系结构的定义]:
>==计算机网络体系结构(Network Architecture)是计算机网络的各层及其协议的集合==。
>
>抽象与实现的关系:
>>计算机网络体系结构是**抽象的定义与结构化规范**，它精确规定了网络系统各层应完成的功能与遵循的接口规范。
>>
>>网络体系结构的实现是**具体的软件与硬件**，即在实际操作系统、芯片固件和网络设备中运行的代码与协议栈。

[分层设计思想的核心价值 (分而治之)]:
>计算机网络是一个极端庞大复杂的分布式系统，分层架构遵循解耦哲学:
>>[1] 各层独立性强: 高层无需关心底层的物理实现细节，只需通过标准接口调用底层服务。
>>
>>[2] 灵活性好: 只要层间接口保持不变，任何一层的内部技术升级(如以太网从铜线升级到光纤)对其他层完全透明。
>>
>>[3] 易于标准化与工程实现: 将复杂庞大的通信问题拆解为模块化的小问题，便于不同设备厂商协同互通。

[不可靠网络的核心设计哲学 (端到端原则)]:
>因特网的设计哲学: ==网络核心尽量简单轻量，网络边缘保持强大与智能==。
>
>>核心网(路由器)只提供简单、不可靠、尽最大努力交付(Best-Effort)的无连接数据报服务，路由器无需维护复杂的连接状态，成本低、抗毁性强。
>>
>>数据传输的差错控制、流量控制、乱序重组与拥塞控制等高级保证，全部交由端系统(主机)的传输层(如TCP)去实现。

###### 2. 三大体系结构模型横向对比矩阵

| 比较维度 | OSI 七层参考模型 (ISO) | TCP/IP 四层参考模型 (DARPA) | 五层教学参考模型 (折中教学) |
| :--- | :--- | :--- | :--- |
| **设计初衷** | 法律上的国际标准 (理论完善，工程繁琐) | 事实上的工业标准 (实践先行，简单健壮) | 综合两者的优点，便于系统化学习教学 |
| **分层结构** | 物理层 $\to$ 链路层 $\to$ 网络层 $\to$ 传输层 $\to$ 会话层 $\to$ 表示层 $\to$ 应用层 | 网络接口层 $\to$ 网际层 (IP) $\to$ 传输层 $\to$ 应用层 | 物理层 $\to$ 链路层 $\to$ 网络层 $\to$ 传输层 $\to$ 应用层 |
| **网络层通信方式** | ==同时支持面向连接与无连接== | ==仅支持无连接服务 (IP数据报)== | 重点讲解网络层无连接IP数据报 |
| **传输层通信方式** | ==仅支持面向连接服务== | ==同时支持面向连接(TCP)与无连接(UDP)== | 同时分析面向连接(TCP)与无连接(UDP) |
| **层与协议关系** | 产生协议前已定模型，通用但缺乏实践经验 | 现有协议族后归纳分层模型，与协议紧密绑定 | 理论框架清晰，协议映射精准 |

<font color=red>【408核心必背命题陷阱: OSI vs TCP/IP 在连接支持上的差异】</font>
>OSI 参考模型: 网络层支持面向连接和无连接；传输层**仅支持面向连接**(OSI认为传输层必须是端到端绝对可靠的保证)。
>
>TCP/IP 模型: 网际层**仅支持无连接**；传输层**同时支持面向连接(TCP)与无连接(UDP)**！

## 2. 五层教学模型各层核心功能与协议全景

###### 1. 物理层 (Physical Layer)

>传输单位: **比特 (bit)**。
>
>主要任务: 在物理传输媒体上透明地传输原始比特流，消除不同物理传输介质在电平、引脚、时钟上的物理差异。
>
>四大接口物理特性(408常考分类):
>>[1] 机械特性: 规定接口所用接插件的规格、引脚数目、排列方式及形状尺寸。
>>
>>[2] 电气特性: 规定信号线上的电压范围、阻抗匹配、传输速率及距离限制。
>>
>>[3] 功能特性: 规定某条信号线上出现的某一电平的物理确切含义(如哪根线是发送、哪根是接收)。
>>
>>[4] 规程特性(过程特性): 规定各物理信号线在执行动作时的时序与先后发生顺序。
>
><font color=red>【408绝对概念红线】: 传输媒体(双绞线、光纤、同轴电缆、无线电波)不属于物理层，不属于计算机网络体系结构的任何一层！传输媒体位于物理层之下，被称为第 0 层或物理介质！</font>
>
>典型设备: 中继器 (Repeater)、集线器 (Hub) (二者均为纯物理层设备，无法隔离冲突域，无法隔离广播域)。

###### 2. 数据链路层 (Data Link Layer)

>传输单位: **帧 (Frame)**。
>
>主要任务: 将网络层下发的 IP 数据报组装成帧，在相邻节点(主机与路由器、或相邻两路由器)之间的链路上无差错地传送帧。
>
>三大基本功能:
>>[1] 封装成帧 (Framing): 在一段数据的前后分别添加首部和尾部，构造帧定界符，确定帧的开始与结束。
>>
>>[2] 透明传输: 无论数据部分出现何种比特组合，都不应被误判为帧定界控制符(采用字符填充或比特填充技术)。
>>
>>[3] 差错检测 (Error Detection): 利用循环冗余检验(CRC)等算法检错，凡校验出错的帧直接丢弃。
>
>寻址机制: 依靠 **MAC 地址(物理硬件地址，48位)** 进行点对点相邻节点寻址。
>
>典型设备: 以太网交换机 (Switch)、网桥 (Bridge) (二者为数据链路层设备，可隔离冲突域，但不能隔离广播域)。

###### 3. 网络层 (Network Layer / 网际层)

>传输单位: **分组 (Packet) / IP 数据报 (IP Datagram)**。
>
>主要任务: 将分组从源主机经由中间网络路由器传输到目的主机，解决跨异构网络的互联互通问题。
>
>核心功能:
>>[1] 路由选择 (Routing): 运行路由协议(RIP、OSPF、BGP)，动态生成并维护全网路由转发表。
>>
>>[2] 分组转发 (Forwarding): 路由器根据转发表将分组从合适的输出接口推送到下一跳路由器。
>>
>>[3] 异构网络互联: 通过统一的 IP 协议屏蔽下层各类以太网、WLAN、ATM 等异构网络的寻址与技术差异。
>>
>>[4] 拥塞控制与网际控制: 配合 ICMP 协议反馈网络连通性与路由差错。
>
>核心设备: **路由器 (Router)** (属于网络层设备，既能隔离冲突域，又能隔离广播域；路由器最高解封装到网络层第 3 层)。

###### 4. 传输层 (Transport Layer)

>传输单位: **报文段 (Segment，TCP)** / **用户数据报 (User Datagram，UDP)**。
>
>主要任务: 负责网络中不同主机上**应用进程之间(Process-to-Process)的端到端通信**。
>
>核心功能:
>>[1] 进程寻址与端口复用/分用: 使用 16 位**端口号 (Port)** 唯一标识主机内的通信应用进程。
>>
>>[2] 端到端的差错控制与完整性校验。
>>
>>[3] 提供两种完全不同的传输服务:
>>
>>$\to$ TCP (传输控制协议): 面向连接、可靠交付、全双工、字节流服务，包含滑动窗口流量控制与拥塞控制。
>>
>>$\to$ UDP (用户数据报协议): 无连接、不可靠、尽最大努力交付、面向报文，开销极小且无时延抖动。
>
><font color=deeppink>【本质辨析: 端到端 (End-to-End) vs 点到点 (Point-to-Point)】</font>
>
>>网络层及以下是**主机到主机 (Host-to-Host)** 的通信，称为“点到点”或“逐跳 (Hop-by-Hop)”通信。
>>
>>传输层及以上是**应用进程到应用进程**的通信，是真正意义上的“端到端”通信。

###### 5. 会话层与表示层 (OSI 专有上层)

>表示层 (Presentation Layer):
>>主要任务: 处理在两台计算机系统之间交换信息的表示方式，解决数据格式的不一致性。
>>
>>核心功能: 数据格式转换(如 ASCII 与 EBCDIC 互转、大端与小端字节序转换)、数据加密与解密、数据压缩与恢复。
>
>会话层 (Session Layer):
>>主要任务: 组织并同步两个会话进程之间的通信，管理数据交换过程。
>>
>>核心功能: 建立、管理和终止会话连接；插入同步检查点 (Synchronization Point)，实现网络中断后的断点续传。

###### 6. 应用层 (Application Layer)

>传输单位: **报文 (Message)**。
>
>主要任务: 直接为终端用户的应用程序提供网络通信交互服务。
>
>典型协议体系:
>>HTTP / HTTPS: 万维网超文本传输协议 (端口 80 / 443)。
>>
>>FTP: 文件传输协议 (控制端口 21 / 数据端口 20)。
>>
>>DNS: 域名系统 (端口 53，基于 UDP/TCP)。
>>
>>SMTP / POP3 / IMAP: 电子邮件传输与拉取协议 (端口 25 / 110 / 143)。
>>
>>DHCP: 动态主机配置协议 (服务器端口 67 / 客户端端口 68)。

## 3. 数据的逐层封装与解封装全过程

###### 1. 数据的端到端封装流动视图

>发送方发送数据时(自顶向下逐层封装):
>
>>应用层: 产生原始应用报文 $\text{Data}$。
>>
>>传输层: 加上传输层首部 $\text{TH}$ (包含源端口号、目的端口号等)，构成**传输层报文段/数据报**。
>>
>>网络层: 加上网络层首部 $\text{NH}$ (包含源 IP 地址、目的 IP 地址、TTL 等)，构成 **IP 数据报(分组)**。
>>
>>数据链路层: 同时加上链路层首部 $\text{LH}$ (包含源 MAC、目的 MAC、类型) 和链路层尾部 $\text{LT}$ (包含 CRC 帧校验序列 FCS)，构成**数据帧**。
>>
>>物理层: 将数据帧转换为一串**原始比特流 (Bit Stream)**，编码为电信号/光脉冲推向传输介质。
>
><font color=red>【两处核心应试细节】</font>
>
>>[1] 仅数据链路层在数据两端同时添加首部和尾部！首部用于地址识别，尾部用于差错校验定界。
>>
>>[2] ==物理层绝不添加任何首部或尾部！== 物理层只作比特流与物理信号之间的编码调制转换，不参与协议数据封装！

###### 2. 中间路由器的解封装与再封装行为

>当一个 IP 分组在网络中穿越路由器时:
>
>>第一步: 路由器物理层接收到线路上涌入的电/光信号，恢复为比特流交给数据链路层。
>>
>>第二步: 链路层解析帧首部与尾部，核对校验和(FCS)，确认目的 MAC 是自己后**剥去链路层首部和尾部**，露出 IP 分组。
>>
>>第三步: 网络层解析 IP 首部，读取目的 IP 地址，将 TTL 减 1 并重新计算首部校验和；查询路由转发表，确定输出接口和下一跳 IP。
>>
>>第四步: 路由器将该 IP 分组下发给该输出接口的数据链路层，**重新封装上针对下一段链路的帧首部与帧尾部**！
>>
>>第五步: 物理层将新帧变为比特流推入下一段物理信道。
>
><font color=deeppink>【路由器解封深度考点】: 路由器是典型的三层设备，在常规数据转发过程中，路由器最高仅解封装到网络层(第 3 层)，绝对不会触碰传输层和应用层的内部数据！</font>

###### 3. 传输过程中地址变化核心定律 (408必考压轴细节)

>全网传输全过程中:
>
>>源 IP 地址 与 目的 IP 地址: ==全程保持不变== (NAT 网络地址转换技术除外)。
>>
>>源 MAC 地址 与 目的 MAC 地址: ==逐跳改变==！每经过一个路由器进行转发，数据链路层都会剥去旧的 MAC 首部，并将源 MAC 替换为当前路由器出接口的 MAC 地址，将目的 MAC 替换为下一跳路由接口或终点主机的 MAC 地址！

## 4. 体系结构核心术语与通信哲学精解

###### 1. 实体与对等实体

>[实体 Entity]: 任何可发送或接收信息的硬件或软件进程。通常指某一具体层次中的某个活动实体(如某个协议模块)。
>
>[对等实体 Peer Entities]: 分别位于不同机器中处于**同一层**的两个活动实体。只有对等实体之间才能通过对等协议进行逻辑通信。

###### 2. 协议 (Protocol) 三要素

>协议定义: 为进行网络中的对等实体之间的数据通信而建立的规则、标准或约定的集合。
>
>协议的本质属性: ==协议是水平的==！即协议只控制对等实体之间的逻辑通信，水平方向的实体必须严格遵循共同协议。
>
>协议的三大核心要素 (408经典高频考点):
>>[1] 语法 (Syntax):
>>
>>$\to$ 数据与控制信息的**结构或格式**。
>>
>>$\to$ 即规定“数据长什么样”，如报文格式、字段顺序、字段占用比特位数、编码方式。
>>
>>[2] 语义 (Semantics):
>>
>>$\to$ 需要发出何种控制信息，完成何种动作以及做出何种响应。
>>
>>$\to$ 即规定“讲了什么内容、要做什么动作”，如请求建立连接、确认应答、超时重发、报错指示。
>>
>>[3] 同步 / 时序 (Timing):
>>
>>$\to$ 事件实现顺序的详细说明。
>>
>>$\to$ 即规定“什么时候做、按什么先后次序做”，如 TCP 三次握手中必须先由客户端发送 SYN，随后服务器回应 SYN+ACK，最后客户端发送 ACK，不可倒置。

###### 3. 服务 (Service) 与服务访问点 (SAP)

>服务的本质属性: ==服务是垂直的==！
>
>>服务是由下层向上层通过层间接口提供的功能调用。
>>
>>低层实体是“服务提供者”，高层实体是“服务用户”。
>
>服务的透明性哲学 (讲义核心手写批注):
>
>>==下层协议的实现细节对上层而言是完全透明的==！
>>
>>上层实体只能通过层间接口看到下层提供的抽象服务能力，下层具体采用了何种复杂协议、何种纠错算法，上层一概看不见，也不需要关心！
>
>服务访问点 (SAP - Service Access Point):
>
>>定义: 同一系统中相邻两层实体交换信息的**逻辑接口**。高层实体正是通过 SAP 访问下层所提供的服务。
>>
>>各层 SAP 映射表 (408极高频核心考点):
>>
>>| 层次 | 服务访问点 (SAP) 的具体名称 | 作用与寻址标识 |
>>| :--- | :--- | :--- |
>>| **物理层 SAP** | 物理接口引脚 / 物理信道 | 标识物理介质上的特定通信信道 |
>>| **数据链路层 SAP** | 逻辑链路控制子层 SAP / 帧中**类型字段 (Type)** | 标识帧内部有效载荷所使用的网络层协议(如 0x0800 表示 IP, 0x0806 表示 ARP) |
>>| **网络层 SAP** | IP 数据报首部中的**协议字段 (Protocol)** | 标识 IP 分组有效载荷所使用的传输层协议(如 6 表示 TCP, 17 表示 UDP, 1 表示 ICMP) |
>>| **传输层 SAP** | 传输层首部中的**端口号 (Port Number)** | 标识主机操作系统内正在运行的具体应用进程(如 80 表示 HTTP, 53 表示 DNS) |

###### 4. 四种服务原语 (Service Primitives)

>原语是操作系统中不可分割的最小执行单元。OSI 定义了四种基本的层间交互服务原语:
>
>>[1] 请求 (Request): 用户层发往服务提供者，要求其完成某项服务功能。
>>
>>[2] 指示 (Indication): 服务提供者发往用户层，通知其发生了某事件(如收到了对方的连接请求)。
>>
>>[3] 响应 (Response): 用户层发往服务提供者，对之前收到的“指示”做出应答。
>>
>>[4] 确认 (Confirm): 服务提供者发往用户层，通知其先前发起的“请求”已经完成并得到对方确认。

###### 5. SDU, PCI, PDU 装配与解装配模型

>三者定义与内涵:
>
>>[SDU (Service Data Unit, 服务数据单元)]: 第 $n$ 层服务用户交付给第 $n$ 层的实际数据净荷 (Payload)。
>>
>>[PCI (Protocol Control Information, 协议控制信息)]: 第 $n$ 层为了实现本层协议功能而附加的控制信息首部/尾部。
>>
>>[PDU (Protocol Data Unit, 协议数据单元)]: 对等层次之间为了实现协议所实际传输的数据单元。
>
>数学关系与装配转换定理:
>
>$$n\text{-PDU} = n\text{-PCI} + n\text{-SDU}$$
>
>$$(n-1)\text{-SDU} = n\text{-PDU}$$
>
>>即: 上一层封装好的 $n\text{-PDU}$，整体作为数据净荷直接传递给下一层，成为下一层的 $(n-1)\text{-SDU}$！
>
>分片与拼接机制:
>
>>分片 (Fragmentation): 若一个 $n\text{-SDU}$ 过大，超出底层最大传输单元(MTU)，底层可以将其切割为多个片段，分别加上 PCI 封装为多个独立 PDU 发送。
>>
>>拼接 (Reassembly): 底层接收到多个分片 PDU 后，剥离 PCI 并重新拼接恢复为原始的单个 SDU 提交给上层。

###### 6. 服务的分类维度

>[1] 面向连接服务 vs 无连接服务:
>
>>面向连接服务: 通信前必须先建立连接，通信过程中维持连接状态，通信结束后释放连接。数据按序传送，可靠性高(如 TCP)。
>>
>>无连接服务: 通信前无需建立连接，随时发送，每个数据包独立寻址转发，不保证按序到达(如 UDP、IP)。
>
>[2] 可靠服务 vs 不可靠服务:
>
>>可靠服务: 网络具有差错校验、确认应答、超时重传机制，保证数据正确、无重复、无遗漏、按序到达。
>>
>>不可靠服务: 网络仅尽最大努力交付，不保证数据无差错、不保证不丢包，差错控制交由上层负责。
>
>[3] 有应答服务 vs 无应答服务:
>
>>有应答服务: 接收方收到数据后必须自动向发送方返回确认信息(ACK)。
>>
>>无应答服务: 接收方收到数据后不返回任何确认信息。

>   ###### **1. [2009 统考真题第33题] OSI 体系结构接口与服务访问点**
>
>   在 OSI 参考模型中，第 $n$ 层向第 $n+1$ 层提供服务，第 $n+1$ 层访问第 $n$ 层服务所使用的逻辑接口被称为：( )
>
>   | A. 传输实体 | B. 服务数据单元 (SDU) |
>   | :--- | :--- |
>   | C. 服务访问点 (SAP) | D. 协议数据单元 (PDU) |
>
>   **【解析与陷阱剖析】**：答案为 **C**。
>
>   > A选项错误: 传输实体是传输层中的活动软件或硬件模块。
>   >
>   > B选项错误: SDU 是层间接口传递的实际数据净荷。
>   >
>   > C选项正确: 同一开放系统中相邻两层实体交换信息的逻辑接口称为**服务访问点 (SAP)**。
>   >
>   > D选项错误: PDU 是对等实体之间交换的协议数据单位。

>   ###### **2. [2010 统考真题第33题] 物理层四大特性概念辨析**
>
>   下列选项中，不属于物理层接口规范定义范畴的是：( )
>
>   | A. 规定接口引脚的数目和物理排列方式 | B. 规定信号线上电平的高低和电压范围 |
>   | :--- | :--- |
>   | C. 规定传输媒体的物理特性(如光纤纤芯材质) | D. 规定各信号线上电平动作的时序与先后关系 |
>
>   **【解析与陷阱剖析】**：答案为 **C**。
>
>   > <font color=red>致命考点: 传输媒体不属于物理层！</font>
>   >
>   > A选项属于**机械特性**。
>   >
>   > B选项属于**电气特性**。
>   >

>   ###### **3. [2011 统考真题第33题] 协议依赖关系**
>
>   在 TCP/IP 体系结构中，直接为 HTTP 提供服务的协议是：( )
>
>   | A. IP | B. TCP |
>   | :--- | :--- |
>   | C. UDP | D. ARP |
>
>   **【解析与陷阱剖析】**：答案为 **B**。
>
>   > HTTP 协议构建在可靠的传输层协议 TCP 之上，直接调用 TCP 建立连接并传送数据。IP 为 TCP 提供服务，ARP 为网络层提供 IP 到 MAC 的地址解析。因此直接为 HTTP 提供服务的是 TCP。

>   ###### **4. [2012 统考真题第33题] OSI 与 TCP/IP 服务特性深度对比**
>
>   在 OSI 参考模型和 TCP/IP 参考模型中，关于网络层和传输层所提供的服务类型，下列叙述正确的是：( )
>
>   | A. OSI 的网络层只提供面向连接服务，TCP/IP 的网际层只提供无连接服务 | B. OSI 的网络层提供面向连接和无连接服务，TCP/IP 的网际层只提供无连接服务 |
>   | :--- | :--- |
>   | C. OSI 的传输层提供面向连接和无连接服务，TCP/IP 的传输层只提供面向连接服务 | D. 两个模型的传输层均只提供面向连接服务 |
>
>   **【解析与陷阱剖析】**：答案为 **B**。
>
>   > <font color=red>【408核心背诵结论】</font>:
>   >
>   > OSI 模型: 网络层“面向连接 + 无连接”均支持；传输层“仅面向连接”(OSI 认为端到端可靠性必须绝对保证)。
>   >
>   > TCP/IP 模型: 网际层“仅无连接”(IP协议尽最大努力交付)；传输层“面向连接(TCP) + 无连接(UDP)”均支持。
>   >
>   > 因此 B 选项叙述完全正确。

>   ###### **5. [2014 统考真题第33题] 协议三要素内涵剖析**
>
>   下列关于网络协议三要素的描述中，正确的是：( )
>
>   | A. 语法规定了通信双方要“做什么”以及做出何种响应 | B. 语义定义了数据与控制信息的结构或格式 |
>   | :--- | :--- |
>   | C. 同步规定了事件实现顺序的详细说明 | D. 协议三要素必须全部在应用层协议中体现，下层协议无需满足 |
>
>   **【解析与陷阱剖析】**：答案为 **C**。
>
>   > A选项错误: 规定“做什么、响应什么”的是**语义**。
>   >
>   > B选项错误: 规定“结构、格式”的是**语法**。
>   >
>   > C选项正确: 同步(时序)详细规定了通信事件发生的先后顺序。
>   >
>   > D选项错误: 所有网络协议(从物理层到应用层)均严格具备语法、语义、同步三要素。
>

>   ###### **6. [2017 统考真题第33题] 各层设备的解封装极限能力**
>
>   某局域网通过集线器、交换机和路由器互联，下列关于这三类设备转发数据时解封装深度的叙述中，正确的是：( )
>
>   | A. 集线器可查看帧的目的 MAC 地址 | B. 交换机最高可查看 IP 数据报的目的 IP 地址 |
>   | :--- | :--- |
>   | C. 路由器最高解封装到网络层并查看 IP 数据报首部 | D. 路由器转发分组时会解封装至传输层以检查端口号 |
>
>   **【解析与陷阱剖析】**：答案为 **C**。
>
>   > 集线器为物理层(L1)设备，仅做电信号中继放大，无法识别任何帧格式和 MAC 地址，A 错。
>   >
>   > 传统以太网交换机为数据链路层(L2)设备，最高只能查看 MAC 地址，无法解析 IP 地址，B 错。
>   >
>   > 路由器为网络层(L3)设备，常规数据转发时最高仅解封装至网络层，读取 IP 首部执行路由查找与 TTL 修改，随后重新封装链路层发送，绝不会解封装至传输层，C 对 D 错。
>

>   ###### **7. [2021 统考真题第33题] 跨路由转发中 MAC 与 IP 地址变化特征**
>
>   主机 H1 向主机 H2 发送一个 IP 分组，途经路由器 R1 和 R2。在分组由 H1 经 R1、R2 最终传送到 H2 的全过程中，下列关于分组头部地址字段变化的叙述中，正确的是：( )
>
>   | A. 源 IP 地址和目的 IP 地址在每一跳都改变 | B. 源 MAC 地址和目的 MAC 地址在全程保持不变 |
>   | :--- | :--- |
>   | C. 源 IP 和目的 IP 全程不变，源 MAC 和目的 MAC 逐跳改变 | D. 源 MAC 和目的 MAC 全程不变，源 IP 和目的 IP 逐跳改变 |
>
>   **【解析与陷阱剖析】**：答案为 **C**。
>
>   > 核心铁律: IP 地址负责全网端到端逻辑寻址，在非 NAT 环境下全程保持不变；MAC 地址负责局部链路点对点物理跳传，每跨越一个路由器接口，链路层均重写帧头，源 MAC 与目的 MAC 逐跳刷新！
