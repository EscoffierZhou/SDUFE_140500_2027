# Chap7.5 散列查找

## 1.散列表的基本概念

由于记录在表中的位置与其关键字之间不存在映射关系,所以结构的查找效率取决于关键字的比较次数

散列函数(哈希函数)是一种将关键字映射到其对应存储地址的函数

>其中,地址可以是数组下标,索引或内存地址

哈希冲突:散列函数可能会将两个或两个以上不同的关键字映射到同一地址

>   同义词:发生哈希冲突的不同关键字
>
>   避免哈希冲突(1):(预防事前)良好的散列函数
>
>   避免哈希冲突(2):(预防事后)

散列表(哈希表):一种根据关键字直接进行访问的数据结构,建立了关键字到存储地址的直接映射;理想情况下,对散列表进行查找的时间复杂度为O(1),和表中元素无关

## 2.散列函数的构造方法

基本要求(1a):定义域范围:散列函数的定义域必须包含所有关键字

基本要求(1b):值域范围:取决于散列表的大小

基本要求(2):地址范围:散列表计算出来的地址应该尽可能均匀分布在整个地址空间

基本要求(3):简单性质:散列函数应该尽可能简单

**1.直接定址法:使用线性函数**

>   ```math
>   H(key) = a\cdot key + b \ (a\not=0)
>   ```
>
>   特点:计算最简单,适用于分布均匀的情形,如果关键字分步稀疏空位多,则浪费

**2.除留余数法:使用除法取余**

>```math
>H(key) = key \ \% \ p
>```
>
>P的选取:选取尽可能接近散列表长度m的质数
>
>特点:形式最简单

**3.数字分析法**

>设关键字是r进制数,其各位上的数码(共r种)出现的频率可能不同
>
>>某些数位上数码分步较为均匀,各种数码出现的机会接近相等
>>
>>某些数码上分步不均,仅有少数几种数码频繁出现
>
>Eg:比如学号前面都有2023,所以应该是$key = 学号\ \% \ 10^8$
>
>**特点:必须提前直到所有关键字集合(静态没有增长)**

**4.平方取中法**

>取关键字平方值的中间几位作为散列函数
>
>>   具体多少位:根据散列表的大小和关键字范围确定
>
>特点:平方运算与所有数码都有关系,所以散列地址分布较为均匀

## 3.散列函数解决冲突

核心思路:如果计算出地址$H_0=H(key)$冲突,则继续计算$H_1,H_2,\cdots$

**1.开放地址法**

使用所有空闲地址存放关键字,地址探测序列由下列递推公式:

```math
H_i=(H(key)+d_i)\%m
```

>其中H(key)为散列函数,$d_i$为第i次探测的增量,m为散列表表长
>
>插入:计算H(key)冲突以后,$d_i$从1开始的增量向后查空位,直到发现空位后插入
>
>查找:计算H(key)冲突以后,$d_i$从1开始的增量向后查元素,中途发现空位后停止

>**一旦选定增量序列则冲突处理方式则被确定**
>
>(1)线性探测法:增量序列:$d_i=1,2,\cdots,m-1$
>
>(2)平方探测法:增量序列:$d_i = 1^2,-1^2,2^2,-2^2,\cdots,k^2,-k^2$
>
>(3)双散列法:增量序列:$d_i=  iH_2(key)$;探测:$H_i = (H(key)+iH_2(key))\%m$
>
>(4)伪随机序列法:增量蓄力由一个伪随机数生成器产生,第$d_i$=第i个伪随机数

**<font color=red>不能直接物理删除表中已有元素,否则会阶段其他同义词的查找路径导致查找失败</font>**

>应该对被删元素所在位置设置一个删除标记,实现逻辑删除
>
>原因:删除了位置相对在前的元素,则指针探测的时候为空,判定后续元素不存在

**2.拉链法**

思路:将统一地址的所有同义词组织成一个链表

```
先入队的在前面:{19,14,23,01,68,20,84,27,55,11,10,79}.H(key) = key%13
0:^
1:01->14->27->79
2:^
3:55->68
4:^
5:^
6:19->84
7:20
8:^
9:^
10:10->23
11:11
12:^
```

## 4.散列查找及性能分析的应用

###### **1.散列表的查找过程**

查找过程(1a):计算Addr=H(key)若为空,则直接失败:

>若存在且相等,则直接查找成功
>
>若存在且不相等,则发生冲突,进入(2)

查找过程(2):如果仅存在,则通过上述的增量方案向后查找

>若存在且相等,则直接查找成功
>
>若存在且不相等or标记DELETED,则继续增量,向后找
>
>若不存在(中途遇到空),则查找失败	

**<font color=red>影响散列表查找效率的三方面:哈希函数,冲突处理方式和装填因子$ \alpha$</font>**

>==**哈希函数的前提:简单均匀散列假设(输入的关键字均匀分布在0~m-1中)**==
>
>**<font color=deeppink>影响性能只有:冲突处理方式(开放地址or拉链法)和装填因子$ \alpha$(表的拥挤程度)</font>**

###### **2.散列表的装填因子$\alpha$**

```math
\alpha = \frac{表中记录数n}{散列表长度m}
```

>   散列表的平均查找长度主要依赖于它,而不是单独的n和m
>
>   如果$\alpha$越大代表:表越满,说明发生冲突的概率更大
>
>   如果$\alpha$越小代表:表越空,说明发生冲突的概率更小

###### **3.散列表的ASL**

**<font color=red>前提:如果是完全的均匀分布!!,在查找的时候只用一次,则存在:</font>**

线性探测法:

```math
ASL_{Linear}\approx \frac{1}{2} \left(1 + \frac{1}{1-\alpha}\right)
```

拉链法:

```math
ASL_{zip} \approx 1 + \frac{\alpha}{2}
```

**如果存在史诗级翻车:**

```
{0, 13, 26, 39, 52, 65, 78, 91, 104, 117, 130, 143},H(key) = key%13
(注:每个关键字计算%13出来都是0,所以查找的时候会连续向后)

第1个元素放 0 号位，比较 1 次。
第2个元素被挤到 1 号位，比较 2 次。
...
第12个元素被挤到 11 号位，比较 12 次。
```

```math
alpha = \frac{12}{16} = \frac{3}{4},ASL_{estimate} = \frac{1}{2}(1+\frac{1}{1-\frac{3}{4}})=2.5
\\ \\
ASL_{real} = \frac{1+2+3+...+12}{12} = \frac{78}{12} = 6.5
```
