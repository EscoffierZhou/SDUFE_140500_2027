# Chap7.2 顺序查找和折半查找

## 1.顺序查找(顺序实现&链式实现)

顺序查找(线性查找)适用于顺序表和链表

>   对于顺序表:可通过递增数组下标依次访问每个元素
>
>   对于链表:通过指针next逐个遍历节点

**适用场景:无序线性表/按关键字有序的线性表**

###### **1.一般线性表的顺序查找**

基本思想(1):从线性表的一端开始,逐个检查关键字是否满足给定条件

基本思想(2):如果查找成功,返回该元素在线性表中的位置

基本思想(3):如果查找失败(查到头了)则返回失败

```C++
typedef struct{
  	ElemTyoe *elem;
    int TableLen;
}SSTable;
int Search_Sq(SSTable ST,ElemType key){
    ST.elem[0] = key;
    for(int i=ST.TableLen;ST.elem[i]!=key;--i); // 后往前找
    return i;	// 查找成功
}
```

>   引入哨兵节点的目的是避免在循环中反复判断数组下表是否越界
>
>   (即不需要额外判断elem[0],如果返回0肯定是错误的)

对于n个元素,第i个元素匹配成功,实际进行了n-i+1次的关键字比较

>查找成功的ASL:==第1项到第n项的求和公式除以n==
>
>```math
>ASL = \sum^{n}_{i=1}P_i(n-i+1) = \frac{n+1}{2}(等概率)
>```
>
>查找失败的ASL:并不累计,所以最坏比较n+1次
>
>```math
>ASL = n+1
>```

**==优化ASL:让高频元素靠近查找起点,降低平均ASL==**

>   情况(1):如果是顺序表,后往前查,则起点是顺序表的尾部n
>
>   情况(2):如果是顺序表,前往后查,则起点是顺序表的头部
>
>   情况(3):如果是链表,起点是头节点所指的第一个节点

###### **2.有序线性表的顺序查找O(n)**

如果在查找之前已知关键字是有序的,则查找失败时后续就不用继续比较了

>   比如按照值大小,从小到大排序,查找顺序是从前往后
>
>   如果elem[i]<key,elem[i+1]>key,则直接判定查找失败

有序线性表的顺序查找应用(顺序查找判定树)

>   其中"圆形"是实际存在的元素;"矩形"是失败节点(n个节点应该有n+1个失败节点)

有序线性表的顺序查找ASL:

>   **到达某一失败结点时所经历的比较次数,等于其父结点所在的层数**
>
>   ==需要注意的是有n+1个比较,多了一个n==
>
>   ```math
>   ASL = \frac{1+2+3\cdots + n+n}{n+1}= \frac{\frac{n(n+1)}{2}+n}{n+1} = 
>   \frac{n}{2}+\frac{n}{n+1}
>   ```

## 2.折半查找<font color=red>(仅顺序存储)</font>

###### **1.折半查找基本概念**

**仅顺序存储的原因:每一次对数组进行折半**

**<font color=red>核心思想:在顺序查找的基础上进行折半,从单枝树变成平衡树$O(log_2n)$</font>**

>   ->因此适用场景是:**关键字有序的线性表(有序可以画单枝树,顺序表可以直接访问)**

基本思想(1):将定值key和中间位置元素进行比较

基本思想(2):匹配成功,则返回对应的位置

基本思想(3):匹配失败,则按照大小返回前半部分or后半部分

```C++
int Binary_Search(SSTable L,ElemType key){
    int low=0, high=L.Table-1 , mid;
    while(low<=high){
        mid=(low+high)/2;	// 所以实现的时候其实是下取整
        if(L.elem[mid]==key)
            return mid;
        else if(L.elem[mid] > key)
            high = mid -1;	// 从最右边移到中间-1
        else:
        	low = mid + 1;	// 从最左边一到中间+1
    }
}
```

>   **额外注意的是,最后会有一次比较(当low=high的时候)elem[low]!=elem[high]**

###### **2.折半查找的ASL**

假设有序表长度为n,则对应的判定树是完全二叉树

>   其中"圆形"是实际存在的元素;"矩形"是失败节点,树高:$h = \lceil log_2(n+1)\rceil$
>
>   查找成功ASL:所有结点的深度之和除以n:(第i层就需要比较i次)
>
>   ```math
>   \begin{align}ASL &= \frac{1}{n}\sum^{h}_{i=1}i\times第i层的结点数量
>   \\ \\ &=\frac{1}{n}\sum^{h}_{i=1}1\times1+2\times2 + 3\times4+\cdots + h \times 2^{h-1}
>   \\\\ 2Sn &= 1\times2^1+2\times2^2 + 3\times2^3+\cdots + h \times 2^{h}
>   \\ \\2Sn-Sn &=   h\cdot 2^h - \frac{1(1-2^h)}{1-2}
>   =h\cdot 2^h - (2^0+2^1+2^2+\cdots 2^{h-1})
>   \\ \\ S_n &= h\cdot 2^h-(2^h-1) = (h-1)\cdot 2^h+1
>   \end{align}
>   ```
>
>   对于满二叉树,$n = 2^h-1$即$2^h = n+1$
>
>   ```math
>   \begin{align}
>   \therefore ASL &=\frac{(n+1)h-(n+1)-1}{n} = \frac{n+1}{n}h-1= \frac{n+1}{n}\lceil log_2(n+1)\rceil-1
>   \\
>   \\ \\ \therefore ASL &\approx log_2(n+1)-1
>   \end{align}
>   ```
>

(130+需要掌握的ASL计算):比如15个节点

>**$ASL_{fail}$<font color=red>(精准)</font>**：$ASL=\frac{10\times 4 + 3\times 3}{13}=\frac{49}{13}$。
>
>>   解释:第n层5个节点,10个失败节点(比较4次);
>>
>>   第n-1的8个枝条占了5个还有3个失败节点(比较3次)
>
>**$ASL_{fail}$<font color=red>(非精准)</font>**：$ASL\approx \log_2(n+1)=log_2(16)=4$。
>
>**$ASL_{success}$<font color=red>(精准)</font>**：$(1\times 1 + 2\times 2 + 4\times 3 + 8\times 4) / 15 = 49/15 \approx 3.27$
>
>**$ASL_{success}$<font color=red>(非精准)</font>**：$ASL\approx \log_2(n+1)-1=log_2(16)-1=4-1=3$。

(130+需要额外处理非满二叉树的情况:先算满树,然后再减去多算的结点)

算法:$h=\lceil log_2(n+1) \rceil$,前$h-1$层全部满员($2^0,2^1,2^2,\cdots,2^{h-2}$),最后一层($n-(2^{h-1}-1)$)

>   $n=12$，后面是 $15(2^4-1)$，所以是 4 层。
>
>   >   $1+2+4=7,12-7=5$
>
>   $n=20$，后面是 $31(2^5-1)$，所以是 5 层。
>
>   >   $1+2+4+8=15,20-15=5$

(130+需要额外处理三等分查找的情况)

原因:ASL会变大,但不是单层节点数变多了,而是判定树不平衡

>   $log_{\frac{3}{2}n}>log_2n$,树变高了,平均查找长度（ASL）自然就增加了

## 3.分块查找(索引顺序查找)

###### **1.分块查找基本思想**

将查找表划分为若干子块(**块内可以无序,但块间必须有序**),同时建立索引表,索引表的每个元素包含对应块的最大关键字和该块的起始地址(**索引表也要按照最大关键字有序排序**)

>   解释:任意前一块的最大关键字 小于 后一块中的所有关键字

###### **2.分块查找过程**

(1):在索引表中确定待查记录所在的块(顺序查找/折半查找)

(2):在块内查找(顺序查找)

**所以分块查找的判定树是两段式:单支树/平衡树+单支树**

###### **3.分块查找的ASL**

分块查找的ASL = 索引查找的平均长度 + 块内查找的平均长度之和

>   假设n个元素被平均分成b块,每块有s个元素(n=bs)

**情况A:块间顺序查找+块内顺序查找**

>```math
>ASL = \frac{b+1}{2}+\frac{s+1}{2} = \frac{s^2+2s+n}{2s}
>```
>
>让ASL最小->如何划分最合理:均值不等式(当$b=s=\sqrt{n}$)
>
>```math
>ASL_{min} = \sqrt{n} + 1
>```

**情况B:块间折半查找+块内顺序查找**

>```math
>ASL = \lceil \log_2(b+1) \rceil + \frac{s+1}{2}
>```

###### **4.分块查找的特例**

如果一个表有 10000 个元素。

>   顺序查找 $ASL \approx 5000$。
>
>   折半查找 $ASL \approx 14$。
>
>   最优分块查找（双顺序）$ASL = \sqrt{10000} + 1 = 101$。

数据库用B+树分块查找的进化版）而不是折半查找，最核心的答案其实是

>   磁盘I/O效率和数据维护成本:磁盘是按照页来的,折半查找会疯狂搞磁头

| **查找方式**        | **适用场景**             | **存储要求**          | **ASL (成功)**          | ASL (失败)            | **维护成本 (增删)**     | **判定树形态**       |
| ------------------- | ------------------------ | --------------------- | ----------------------- | --------------------- | ----------------------- | -------------------- |
| **顺序查找 (无序)** | 数据量小、完全乱序       | 随便 (顺序/链式)      | $(n+1)/2$               | $n$                   | **极低** (直接插尾部)   | 单支树（竹竿）       |
| **顺序查找 (有序)** | 链表存储但要求查找失败快 | 随便 (顺序/链式)      | $(n+1)/2$               | $\approx n/2$         | **中等** (需保持有序)   | 单支树（带失败节点） |
| **折半查找 (有序)** | 静态表、查找极其频繁     | **必须顺序存储**      | $\approx \log_2(n+1)-1$ | $\approx \log_2(n+1)$ | **极高** (移动大量元素) | **平衡树 (矮胖)**    |
| **分块查找**        | **动态平衡**、数据量大   | **索引顺序+数据随意** | $\approx \sqrt{n} + 1$  | 取决于块间边界判定    | **低** (只需在块内操作) | 混合树               |
