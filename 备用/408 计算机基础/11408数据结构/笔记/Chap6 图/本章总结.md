## 题目中的问题

#### 漏洞 1：充分必要条件的“过度映射”（代数与几何的错位）

充分必要条件的“过度映射”（代数与几何的错位）

**Bug 表现：** 认为拓扑序列唯一，图的网线就是唯一的；认为有向无环图（DAG）就是三角矩阵，所以是对称的。

**系统补丁：**

-   **降维丢失：** 图（二维网线）被拓扑排序压扁成序列（一维数组）时，会丢失大量冗余依赖信息。所以**序列唯一，绝推不出图唯一**。
-   **唯一性底线：** 序列唯一只代表图里有一条贯穿全场的**哈密顿路径（单线主心骨）**。
-   **矩阵物理学：** 只有**无向图**的矩阵是完美的对称（双向奔赴）。DAG 映射的是上三角矩阵，代表绝对的不对称（单向碾压）。

#### 漏洞 2：贪心引擎的“边界失明”（MST 专属陷阱）

**Bug 表现：** 在 Prim 选边时选了两个都在未探索区域的点；认为 MST 里的边一定比没选的边便宜。

**系统补丁：**

-   **Prim 的雷达盲区：** Prim 必须、绝对只能在**“已开发区”和“未开发区”的交界处**找最便宜的边。内部互砍它看不见！
-   **MST 的桥梁锁死：** 为了保证“连通”这个最高物理定律，如果两个城市群之间只有一条造价 100 万的桥，MST 也必须捏着鼻子买下它，哪怕城市群内部有很多被抛弃的造价为 1 的小路。

#### 漏洞 3：算力越界与引擎误用（算法互斥性）

**Bug 表现：** 用 Prim 去算无权图的最短路径；认为 Dijkstra 不适合算多源最短路。

**系统补丁：**

-   **无权图最短路引擎：** 绝对是 **BFS**！用 Prim 是物理级错误（Prim 算的是连通总造价，不是通勤距离）。
-   **Dijkstra 的战区：** 它虽然是单源引擎，但只要套一个 `for` 循环跑 $V$ 次，它在稀疏图上算多源最短路的速度，能把 Floyd 按在地上摩擦！

#### 漏洞 4：时间轴上的“偷窃”与“死锁”（AOE 与 AOV）

**Bug 表现：** 在算 $l(i)$ 时剥夺非关键活动的摸鱼时间；认为入度为 0 的点多了会导致拓扑失败。

**系统补丁：**

-   **AOE 摸鱼定律：** 算 $l(i)$ 时，眼睛必须死死盯住它的**终点死线 $vl$**。只要终点不催，这个活动就可以疯狂摸鱼（余量变大）。
-   **AOV 死锁本质：** 并发点（多个入度 0）只会让序列不唯一，**绝对不会**导致排序失败。真正的失败只有一种：**环（互相等待，死锁崩溃）**。

### 第三战区：图论引擎兼容性矩阵 (Firmware Table)

为了解决你“什么算法对应什么图记忆不牢”的问题，直接把这张表固化：

| **物理引擎**         | **适用图纸类型 (Input)** | **绝对禁止的毒药 (Fatal Error)**     | **核心产物 (Output)**             |
| -------------------- | ------------------------ | ------------------------------------ | --------------------------------- |
| **BFS**              | 无权图 (或权值全为 1)    | 边带有不同权重                       | 最少跳数 / 最短路径               |
| **Prim / Kruskal**   | 无向带权图 (连通图)      | 有向图（通常不考有向 MST）           | 连通全图的最便宜网线集合          |
| **Dijkstra**         | 有向/无向带权图          | **负权边** (直接摧毁 Final 锁死机制) | 单源点到其他所有点的最短路        |
| **Floyd**            | 有向/无向带权图          | **负权环** (无限刷钱漏洞)            | 任意两点间的绝对最短路径          |
| **Topological Sort** | **AOV网 (DAG)**          | 存在任何形式的环 (死锁)              | 任务执行的一维线性流              |
| **AOE (ve/vl 矩阵)** | **AOE网 (DAG)**          | 存在任何形式的环 (工期无限)          | 零容错率的致命工程瓶颈 (关键路径) |
